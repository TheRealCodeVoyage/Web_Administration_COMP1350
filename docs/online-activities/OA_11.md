# Online Activity 11: Logging & Analytics Recap

*COMP 1350 — Web Administration — distributed Week 11, due before Week 12*

## Why This Matters

This is the last content week of the course. Everything so far has been about making a site run and run well. Week 12 is about knowing what's actually happening on it — both from an operations angle (logs) and a business angle (analytics). This is also your last full lecture before Milestone C and the course wrap-up.

## Before Class: Read

- [DigitalOcean — An Introduction to Logging](https://www.digitalocean.com/community/tutorials/an-introduction-to-logging) *(search "DigitalOcean intro to logging" if this link moves)* — general concepts of application/server logging
- [Google Analytics Help — What is Google Analytics 4?](https://support.google.com/analytics/answer/10089681) — official overview of GA4
- [Google — GA4 vs. Universal Analytics differences](https://support.google.com/analytics/answer/11583528) — skim; you don't need details, just the reason GA4 exists

## Come to Class Ready to Answer

1. Your Nginx and Node app both produce log files by default, sitting on individual servers. Now that you have multiple servers (Weeks 9-10), what problem does that create for someone trying to debug an issue?
2. What is a "centralized log server," in your own words? What would you need to change about how each server handles its logs to make that work?
3. Google Analytics tracks visitor behavior, not server performance. What are two examples of business questions GA4 could answer that a server access log could not?
4. Can you think of one privacy or compliance concern that comes with collecting detailed visitor analytics?

## How This Feeds Forward

- These questions form part of **Quiz 11**, given in Week 12 — the last weekly quiz of the course.
- Week 12's lecture and lab set up a centralized logging pipeline and instrument a live site with GA4, directly answering questions 1-3 above. Milestone C is also due this week.
